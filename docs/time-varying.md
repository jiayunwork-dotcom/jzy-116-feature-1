# 时变负荷（负荷曲线）能力说明

本文档说明在原 M/M/1/K 稳态解析/仿真服务之上新增的“时变负荷”能力：
数据模型、瞬态求解方法的取舍、分段仿真的随机数方案、增量复用判定规则、
段边界状态保存、持久化方式与各项数值容差。

老的三个接口（`POST /api/analytic`、`POST /api/simulation`、
`POST /api/compare`）的路径、请求/响应字段、错误语义**完全不变**，同一组
参数与种子结果逐位一致，且**不读写任何存储**（时变模块挂在独立路由、
独立数据目录上，存储目录懒创建）。

---

## 1. 要解决的问题

稳态解析值的前提是“到达率恒定、系统早已平衡”。晚高峰这种一天内到达率
起起落落的场景里：

- 高峰刚开始几分钟系统还没被填满，瞬态阻塞概率低于稳态值；
- 高峰刚过时积压还没排完，队长/利用率仍被上一段的历史拖着；
- 改了流量曲线上的一段，需要立刻看出“从那一段起”的差别，而不是每次
  都整条曲线重算。

本能力把时间轴切成首尾相接的若干**时段（segment）**，从系统为空开始、
状态在段间连续延续地走一遍整条曲线，每段同时给出**瞬态解析**与
**固定种子仿真**两套时间平均指标，并支持“改一段只重算该段之后”的
增量核算。

## 2. 数据模型

### 2.1 曲线（Curve）与版本（Version）

登记一条曲线时固定三样**全曲线不变**的量：

| 字段 | 含义 |
| --- | --- |
| `mu` | 服务率 μ，整条曲线上恒定 |
| `capacity` | 系统总容量 K（含正在服务的 1 个），整条曲线上恒定 |
| `seed` | 仿真固定种子（uint32，缺省 1），曲线各版本共用同一条随机数体系 |

时间轴由若干**时段**组成，每段只有两个量：

| 字段 | 含义 |
| --- | --- |
| `duration` | 时段时长 d_k（> 0） |
| `lambda` | 该段到达率 λ_k（允许 0，表示该时段无到达；不允许负） |

版本是**只增不改**的：每次改曲线都提交一份**完整时段表**，服务端分配
单调递增的版本号（从 1 开始），记 `parentVersion` 为上一版。老版本与其
核算结果永久保留，凭版本号原样调出，不会被覆盖。

### 2.2 核算（Computation）

对某版本发起一次核算，结果与 `(curveId, version)` 绑定、不可变：

- 从系统为空开始（解析入口分布 δ_0、仿真入口队长 0）；
- 段与段之间状态连续延续，绝不逐段清零；
- 每个段结果含三部分：
  - `analytic`：瞬态解析（段内时间平均阻塞概率/平均队长/平均等待/利用率，
    以及**段末人数分布** `endStateProbabilities`，长度 K+1）；
  - `simulation`：固定种子仿真的同口径经验值；
  - `comparison`：每样指标的解析/仿真值与绝对差；
- 每个段带布尔标记 `reused`：本次核算中该段是复用的前缀还是重算段；
- 顶层 `mode`（`full` / `incremental`）与 `firstRecomputedIndex`
  标明复用范围。

核算**幂等**：对已核算版本重复发起，返回持久化的原样结果（`alreadyComputed:true`）。

另有只读核对参数 `{"forceFull": true}`：无论是否核算过，都实时从空系统
完整重算一遍且**不落盘**，专门用来核对“增量结果 == 完整重算”。

### 2.3 上限

为把瞬态向量传播成本（随 K 线性）和拥塞段的仿真事件数控制住，约定：

| 项 | 上限 | 理由 |
| --- | --- | --- |
| 时段数 | `64` | 覆盖一天按刻钟/分钟切片；再多通常是采样口径选错 |
| 单段时长 | `1000` | 配合速率上限，单子步与单段事件数可控 |
| 曲线总时长 | `10000` | 防止 λ 大时事件数无界 |
| 容量 K | `1000` | 瞬态要传播 K+1 维向量；数百已覆盖晚高峰诉求 |
| λ / μ | `10000` | 仿真在拥塞段事件数 ∝ λ·d，封顶防止单机跑爆 |
| seed | `[0, 2^32-1]` 整数 | mulberry32 的 32 位状态空间 |

超限、时段时长非正、到达率为负、引用不存在的曲线/版本，分别返回
`400`（带 `error` 字符串与 `fields` 字段说明）或 `404`。

## 3. 瞬态解析：为什么选均匀化（uniformization）

### 3.1 模型

段内 λ、μ 为常数，状态 n = 0..K，满足生灭过程向前方程 `p'(t) = p(t)Q`，
其中 Q 是三对角生成元。取均匀化速率 `α = λ + μ`，写成 `Q = α(P − I)`，
P 是行随机矩阵（在 n 处以 λ/α 概率上跳、μ/α 概率下跳、对角补齐）。于是

```
p(d) = p(0) · Σ_{m=0}^∞ e^{-αd}(αd)^m/m! · P^m
```

即“参数 αd 的 Poisson 个离散链步数”的混合。实现见
`src/timvar/transient.ts`。

### 3.2 选它、放弃了什么

| 方法 | 取舍 |
| --- | --- |
| **均匀化（选用）** | 离散转移 P 与 Poisson 权重**全部非负**，只要截断留足尾概率，分布严格非负、质量归一；无负概率、无 NaN，λ≫μ、K 到数百都稳。每步是一次 O(K) 的三对角稀疏乘法。代价是 Poisson 项数随 αd 线性增长，用“子步 + 稳态提前退出”处理。 |
| 显式 Euler / RK 类直接积分 ODE（放弃） | 步长受稳定性条件 α·h < 2 限制，λ 很大时步要极小；更关键的是这类方法每步都有正负项相消，舍入误差会产生**负概率**，λ≫μ、K 大时尤其明显，要不断做非负化修补，难以给出干净的误差口径。 |
| 特征值/矩阵指数精确对角化（放弃） | 三对角矩阵的谱分解在 K 几百时成本 O(K³) 量级，且特征值在临界 ρ≈1 附近数值敏感；为一个本身就是数值近似的结果付出这个代价不划算。 |
| 稳态闭式（老接口） | 只在平衡时成立，直接回答不了“高峰头几分钟/刚过峰”的问题。 |

### 3.3 时间平均指标的求法

要的是段内时间平均 `(1/d)∫₀ᵈ f(p(t))dt`。阻塞概率、平均队长、利用率都是
p 的**线性**泛函（`p_K`、`Σ n·p_n`、`1−p_0`），所以只需算“时间平均分布”。
利用 Poisson–Gamma 恒等式

```
∫₀ᵈ e^{-αt}(αt)^m/m! dt = (1/α)·P(Poisson(αd) > m) = (1/α)(1 − Σ_{j=0}^m w_j)
```

第 m 步对“时间平均分布”的权重是 `(1/α)` 乘 Poisson 尾概率，一次推进同时
得到段末分布与时间平均分布，不需要在内部时间网格上反复采样。

### 3.4 数值实现要点与误差口径

- **Poisson 权重从众数展开**：不能从 `w_0 = e^{-αd}` 起步递推，αd 超过约
  700 时 `e^{-αd}` 在 double 里下溢成 0，整条递推全 0（高 λ、长段必踩）。
  改为从 `m0 = floor(αd)`（众数）用对数空间定初值（众数处 pmf 恒为
  O(1) 不溢出），再按比值向两侧展开，最后整体归一。
- **子步**：单子步均值上限 `MAX_MEAN_PER_SUBSTEP = 2000`，αd 更大时把段
  切成等长子步逐段推进。
- **稳态提前退出**：某子步段末分布与本段稳态分布逐状态最大差小于
  `1e-12` 时，剩余子步直接以稳态分布填充（已平衡的链再演化不变）。
  这是 αd 巨大的拥塞段的性能保护，数值上不引入可分辨差异。
- **截断**：Poisson 上尾截断到尾概率 < `1e-13`。
- **清洗**：仅把绝对值 < `1e-12` 的浮点“负零”夹到 0，再整体重归一
  （仅在 `|Σp−1| ≤ 1e-9` 时）；归一误差超过 `1e-9` 直接报错而不是掩盖。

**整体误差口径**：段末分布与时间平均分布的绝对误差（相对稳态/精确解）
在文档给定上限内**不超过约 1e-9**（截断 1e-13 + 每子步舍入累积），常态
参数下实测在 1e-12 量级。这远小于仿真的统计误差，所以解析/仿真对照里
观察到的差距来自仿真随机性，而非瞬态求解误差。

### 3.5 每段是纯函数

`evolveSegment(入口分布, λ, μ, K, d)` 是确定性纯函数：同样入参逐位同结果，
不依赖段的绝对位置、不依赖后续段。这是解析侧“增量重算与完整重算逐位
一致”的根本保证——第 k 段只取决于入口分布（第 k−1 段段末）与本段参数。

## 4. 分段仿真：随机数流与段边界

### 4.1 为什么不能所有段共用一条顺序消耗的随机数流

一个朴素做法是：所有段共用一条 mulberry32 流，边界上保存 RNG 内部状态
续接。这有个致命问题——**第 k 段 λ 一改，本段发生的事件数就变，消耗的
随机数个数就变，后面每一段抽到的随机数全部错位**。于是即使前缀段参数
完全相同，它们段末的 RNG 状态也不同，前缀无法复用；“增量 == 完整重算”
在仿真侧不可能成立。

### 4.2 方案：每段一条确定性派生的独立子流

第 k 段的 RNG 种子由 `(曲线种子 seed, 段下标 k)` 经确定性整数函数派生
（`seedForSegment`，见 `src/timvar/segment-simulation.ts`）：

- `k = 0` 时**恒等返回 seed** —— 保证单段曲线的分段仿真与老
  `/api/simulation` 的 `maxTime` 停止结果**逐位一致**（验收三）；
- `k ≥ 1` 用 splitmix32 风格混合得到 uint32 子流种子。

于是“第 k 段抽到的随机数”只取决于 `(seed, k)`，与任何前缀段的时长/
到达率无关。这不是人为干预随机过程：分段常数速率的 NHPP 本来就是“每段
一条互相独立的齐次 Poisson 到达流”，各段 Exp 间隔彼此独立正是模型本身
的语义；子流只是把这种独立性实现成**可寻址、可复现、可重启续算**的形式。

### 4.3 段边界保存什么

段边界上只持久化**跨界物理状态**（`CarryState`）：

```
{ numberInSystem, pendingDepartureTime }
```

- `numberInSystem`：段末系统内人数（下一段初始队长）；
- `pendingDepartureTime`：段末仍在系统中的那个顾客**已抽样的离开时刻**
  （全局绝对时间）。单服务台保证任意时刻至多一个在途离开；
  服务不被段边界打断，该时刻作为确定性状态跨界携带、不重抽。

**不保存 RNG 内部状态**：子流种子可由 `(seed, k)` 随时重新派生，无需落盘。

**跨界到达的处理**：跨界的“待处理到达”事件一律丢弃，下一段从边界时刻
用本子流的第一个随机数抽 `Exp(λ_{k+1})` 作为首个到达间隔。这是精确构造
而非近似——相邻段是两条独立 Poisson 到达流，独立增量本就不该跨界携带。
（被丢弃事件对应的随机数消耗在本段子流内部，不影响任何别的段。）

下一段开跑时用全新事件表：先放入跨界保留的离开（若有），再排本段第一个
到达。同时刻平局由事件表插入序号裁决；完整重算与增量重算走同一条重建
路径，裁决顺序一致。

### 4.4 为什么这样能逐位一致

- 解析侧：每段是入口分布与本段参数的纯函数（3.5）。
- 仿真侧：第 k 段的随机数只由 `(seed, k)` 决定；跨界物理状态只由前一段
  段末决定。因此第 k 段输出只取决于“第 k−1 段段末的人数/在途离开”与
  本段参数。改第 k 段只改变从 k 起的状态，前缀 0..k−1 的输入逐位不变，
  其结果就逐位不变，直接复用；从 k 起重算的每一段与完整重算走的是
  **同一个纯函数、同一份输入**，故逐位相同。
- 复用只做 `structuredClone`（内存）与 `JSON.parse(JSON.stringify)`
  （跨重启）：double 按 IEEE-754 最短十进制往返，位模式不变。

## 5. 增量复用判定规则

新版本 `v` 相对父版本 `p` 的时段表逐段比对：

- `firstDifferentIndex` = 第一个“时长或到达率不同”的最小下标；
  新表更长（末尾追加）时，差异点等于旧表长度；
- 若首版、或父版本尚未核算、或显式 `forceFull`：从空系统**完整核算**
  （`mode='full'`，`firstRecomputedIndex=0`）；
- 否则第 `0 .. k-1` 段从父版本核算结果**原样复用**（`reused=true`，含解析、
  仿真、段末分布与跨界状态），从第 k 段入口状态接着算（`reused=false`），
  `mode='incremental'`，`firstRecomputedIndex=k`。

判定依据严格只看“段自己及其之前的段”，任何段都不读取后续时段。缩短
（删段）也安全：新表是旧表的某段前缀时，差异点为新表长度。

## 6. 持久化

- 形式：**每条曲线一个 JSON 文件**，`<dataDir>/curves/<curveId>.json`。
  文件内容是曲线聚合根：元数据 + 全部版本 + 各版本核算结果（含每段末
  跨界状态）。零新依赖，`node:20-slim` 底座不用改。
- 访问模式是“按 id 取整棵聚合”，版本只增、核算一次绑定，单文件即可覆盖。
- 写入原子性：写同目录临时文件再 `rename`，崩溃最多留下旧文件或 `.tmp`，
  不会读到写了一半的 JSON。同步 IO + Node 单线程请求处理，同一曲线写操作
  天然串行，无需进程内锁。
- **double 逐位往返**：`JSON.stringify/parse` 对 IEEE-754 double 用最短
  十进制表示，读回是同一个 double —— 这是重启后增量仍逐位一致的前提。
- 数据目录通过 `TIMVAR_DATA_DIR` 指定（默认进程工作目录下 `./data`），
  懒创建：只有真正写时才建目录。老接口全程不碰存储。

## 7. 误差与容差（验收口径）

- 瞬态解析数值误差（文档上限内）：段末/时间平均分布绝对误差 ≲ **1e-9**。
- 瞬态 vs 稳态（验收一）：单段、λ 不变、时长足够长时，段末瞬态分布与
  老稳态解析接口逐状态最大差 < **1e-7**；空系统起步最初极短窗口时间平均
  阻塞概率 < **1e-6**。
- 概率合法性（验收二）：所有段末/时间平均概率非负（允许 −1e-12 内夹零）、
  和为 1（误差 ≤ 1e-9），λ≫μ、K 数百无 NaN/负数。
- 仿真复现（验收三）：单段曲线分段仿真与老 `/api/simulation` 的 `maxTime`
  结果在同口径字段上**逐位相等**。
- 经验 vs 瞬态（验收四）：每段都充分达到该段平衡（时长数十倍混合时间、
  每段数万到达）时，经验阻塞比例差 < **0.01**、利用率差 < **0.01**、
  平均队长差 < **0.1**。注意在真实时变的爬坡/回落段，瞬态值与稳态值
  本身会显著不同——这正是本能力存在的意义，此时应以瞬态解析为准，
  不应拿稳态值对监控。
- 增量一致性（验收五、六）：增量结果与完整重算在所有数值字段（解析、
  仿真、跨界状态）上**逐位相同**，唯一允许差异是各段的 `reused` 标记本身。

## 8. 模块划分

```
src/timvar/
  types.ts              曲线/版本/核算/段边界的类型
  validation.ts         时变输入校验（上限、带 fields 的错误）
  transient.ts          瞬态求解：均匀化、Poisson 权重、稳态提前退出、指标
  segment-simulation.ts 分段 DES：子流派生、段边界跨界状态、runSegment
  storage.ts            JSON 文件存储（原子写、读缓存、懒目录）
  service.ts            曲线/版本生命周期、增量判定与核算编排
  routes.ts             /api/curves/... 路由
```

老模块仅有的两处**向后兼容的增量**改动：
- `TimeWeightedAccumulator.settle(endTime, startTime=0)` 增加可选起始时刻
  （默认 0，老引擎调用逐位不变），并新增 `start()` 登记非空初态；
- `server.ts` 在 `PORT=0` 时日志打印操作系统实际分配的端口（便于测试）。

老的 `Rng`、仿真引擎、解析引擎本身**零改动**：分段仿真复用 mulberry32
发生器与事件表，但随机数续接通过“每段重新派生种子”而不是暴露/保存 RNG
内部状态实现。
